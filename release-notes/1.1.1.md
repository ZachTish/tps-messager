# TPS Notifier 1.1.1

## Intent

Reduce redundant diagnostic console work during settings persistence while preserving every delivery and logging behavior.

## Changes

- Announce debug activation only on a real disabled-to-enabled transition.
- Keep enabled diagnostics active across repeated settings synchronizations without repeating the activation line.
- Emit the final plugin-unload trace before resetting logger state, preserving a clean activation on a later lifecycle and suppressing stale post-unload diagnostics.
- Preserve ntfy transport, manual composer, dry-run, protocol aliases, settings persistence, public APIs, error logging, and all settings/data contracts. No migration is required.

## Before/after evidence

- The released 1.1.0 logger emitted 100 activation console lines for a synthetic burst of 100 redundant `setLoggingEnabled(true)` calls.
- Version 1.1.1 emits one activation line for the same burst—a 99% reduction in that redundant-announcement path.
- The focused regression also confirms that enabled diagnostics still emit, disabled diagnostics remain suppressed, a later disabled-to-enabled transition announces again, and unload resets state after its final trace.
- This measurement covers activation-announcement console emissions, not all logger work or all settings-save work.

## Validation

- Focused logger/lifecycle tests: 2 passed.
- Full declared suite: 28 passed.
- Required separate production-mode build: passed and deployed only to the registered Obsidian Plugin Test Vault.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**. Delivery, Composer, and Diagnostics settings destinations rendered with delivery disabled; no setting was changed and neither Dry Run nor Send Test was invoked.
- Runtime `data.json` remained absent.
- Production was not accessed or modified.

## Compatibility and limitations

- Minimum Obsidian version: 1.10.0.
- Delivery still requires an explicitly enabled transport, a valid ntfy server, and a topic.
- Automatic retry/backoff and a rolling delivery history are not part of this release.
- The dependency cache audit reported the repository's existing development-only dependency findings; no forced dependency upgrade was included in this runtime patch.
