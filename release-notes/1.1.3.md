# TPS Notifier 1.1.3

TPS Notifier `1.1.3` is a backward-compatible logger performance and reliability patch. It removes a quadratic cleanup path from high-cardinality diagnostic bursts while preserving the complete released delivery feature set.

## Changes

- The logger retains the earliest possible dedupe-entry expiry and skips cleanup scans before that time.
- Every accepted timestamp can move the cleanup deadline earlier while the map remains above the 300-key threshold.
- A cleanup that drops the map to 300 entries or fewer resets the deadline, making the next threshold crossing perform a fresh authoritative scan even after clock movement.
- The exact dedupe key, 3,000 ms suppression boundary, strict cleanup expiry rule, logging toggle, always-on errors, console method and arguments, serialization fallback, scoped logging, and unload behavior are unchanged.
- ntfy delivery, HTTP classification, retry policy, dry runs, manual composer behavior, settings, commands, protocols, public APIs, and persisted data are unchanged.

## Before/after evidence

- The untouched exact public `1.1.2` baseline passed all 29 declared tests and its contained production build before editing.
- The new focused regression first failed against released behavior with 700 full-map scans for 1,000 accepted unique errors.
- The candidate emits the same 1,000 errors with one scan, preserves suppression just inside the window, accepts at exactly 3,000 ms, scans after expiry, and preserves output across a backward-forward-backward synthetic clock sequence.
- One million deterministic randomized bundled events produced zero differences in emitted console method/arguments or retained-map contents.
- Differential coverage included log/debug/info/warn/error/flow gating, enable transitions, identical and distinct keys, 2,999/3,000/3,001 ms boundaries, positive jumps, clock regressions, circular values, throwing `toJSON`, `BigInt`, symbols, functions, `undefined`, and `Error` values.
- The crafted stale-schedule sequence verifies cleanup below the threshold, insertion under a regressed clock, a later threshold crossing, and a second regression; both versions emit the formerly expired key and finish with identical maps.
- On 8,000 accepted same-time messages, full scans fell from 7,700 to one and map-entry visits from 31,958,850 to 301.
- Across 15 interleaved timing rounds, median time fell from 217.502 ms to 3.064 ms (98.59%).
- Both versions retain all 8,000 live entries, retain them at exactly 3,000 ms, and reduce to the same two entries after one accepted event at 3,001 ms. Suppressed messages trigger no cleanup in either version.
- Production-style bundle size increased from 20,661 to 20,803 bytes (+142 bytes, 0.687%) for the one numeric expiry marker and guarded cleanup.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.10.0`.
- No settings or data migration is required.
- The logger still allows a same-time high-cardinality burst to retain more than 300 keys until time advances and another accepted message makes expiry possible. That matches released cleanup and dedupe behavior; this patch removes useless scans, not the dedupe history itself.
- The legacy `tps-notifier` protocol alias, fallback notification body, fail-closed settings behavior, and Controller-facing APIs remain because they preserve supported compatibility or safety.
- Automatic delivery retries remain intentionally absent because retrying an ntfy POST after an uncertain outcome can duplicate a notification.
- Existing development-only dependency audit findings are unchanged and are not bundled into the plugin runtime.
